PsychApp / PsychDeep 1.2

A development and research project for longitudinal self-report, professional follow-up and risk monitoring in stimulant-use and chemsex contexts. It combines patient, therapist/supervisor and clinical-administration interfaces with a deterministic risk engine and AI-assisted text analysis. Risk calculations and model-derived signals are kept traceable to their source data. It is not a validated medical device or diagnostic system.

How I work on these projects

I use the clinical problem to define the scope, then work through the data model, application logic, interface and deployment. In health-related software I try to keep technical behaviour, uncertainty and limitations visible rather than treating the interface as the whole product.

1. Define scope and limitationsSpecify intended use, users, data sources, exclusions and safety boundaries before adding automation.
2. Build end to endConnect interface, API, database and deployment so integration problems appear early.
3. Check the deployed systemCompare the running service with the repository and configuration instead of assuming local behaviour carries over unchanged.
4. Document changesKeep technical notes and release history so decisions, limitations and changes remain inspectable.
