PsychDeep 1.2

A development and research prototype for longitudinal self-report, professional follow-up and risk monitoring in stimulant-use and chemsex contexts. The current architecture combines patient and professional interfaces, a deterministic 0–4 risk engine, a three-role LLM layer and traceable source evidence. The LLM can extract, converse and assist review, but it does not decide the alert level. It is not a validated medical device, diagnostic system or emergency service.

How I work on these projects

I use the clinical problem to define scope, then work through the data model, application logic, interface, testing and deployment. In health-related software I try to keep technical behaviour, uncertainty and limitations visible rather than treating the interface as the whole product.

1. Define scope and limitationsSpecify intended use, users, data sources, exclusions and safety boundaries before adding automation.
2. Separate inference from authorityUse model outputs as inspectable signals while keeping clinical or risk decisions in deterministic, reviewable logic where the project requires it.
3. Build end to endConnect interface, API, database and deployment so integration problems appear early.
4. Test the deployed contractSchema verification, CI, migration idempotence and source traceability matter as much as a local green screen.
